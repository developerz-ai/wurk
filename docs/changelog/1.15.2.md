# 1.15.2 — 2026-11-21

Backport onto 1.15.1.

### Fixed

- **Sidekiq Pro's private lists are reclaimed.** Pro 7.3 keeps in-flight jobs in `queue:sq|<host>:<pid>:<nonce>|<queue>`. Wurk could not read that name, so the jobs of a Pro process that died before the cutover stayed there, reported as unparseable. The reaper now returns them to their queue, keeping a `|` in the queue name.
- **A Pro list could be drained from a live owner.** A Pro queue name ending in `|<digits>|<digits>` was misread as a Wurk list on a queue called `sq`, so its owner was judged by a heartbeat that does not exist and its jobs moved to the wrong queue. A name that reads as both shapes is now refused and reported.
- **A public queue whose name reads as a private list is no longer drained.** The reaper checks the `queues` set before it treats such a key as orphaned.
- **A private-list key with invalid UTF-8 no longer aborts the reaper's sweep.** It is reported as unparseable.

### Upgrade notes

- A Pro list is reclaimed only after its owner's heartbeat hash (`<identity>`, field `info`) has been gone for the reaper's grace. Heartbeats cannot see a process that is running but cut off from Redis for longer than that, so **stop every Pro worker before starting Wurk**.
- A reclaimed job runs again, as it would under Pro. A job that was killed partway through must be safe to repeat.
- No Redis key, job format or configuration change.
