# 1.22.0 — 2026-11-26

### Added

- **The heartbeat reports the container's limits.** `info` gains `cpu_limit` (CPUs, may be fractional, from cgroup v2 `cpu.max` or v1 `cpu.cfs_quota_us`) and `memory_limit_kb` (from v2 `memory.max` or v1 `memory.limit_in_bytes`), each null unless the cgroup caps tighter than the machine. `cores` and `memory_total_kb` stay the machine's, which inside a pod is the node's. Both new fields ride `/api/processes` and `/v1/swarm`'s hosts; Sidekiq Web ignores them.

### Changed

- **Busy page: a pod's memory reads against its limit.** RSS showed over the node's RAM (`612 MB / 31.0 GB` in a 2 GB pod) and CPU as the node's cores; it now shows `612 MB / 2.0 GB limit` and `2 CPUs (limit)`, with the node's figures in the tooltip. Bare metal and macOS read as before.
- **Busy page: hosts of one process share one grid.** Every Kubernetes pod is its own host, so each single-process pod got a header row and a single card, a long scroll for ten pods. Those cards now fill a responsive grid (several per row, one on a phone) and carry the hostname and limits themselves; a host running several processes keeps its section. Cards are more compact, and a queue list past six collapses behind a `+N more` toggle.

### Fixed

- Page headers wrap on a phone instead of squeezing the summary to a word per line and pushing the page actions off screen.
