# Unreleased

### Added

- **sidekiq-unique-jobs, native: drop the gem, keep the code.** Wurk carries sidekiq-unique-jobs 8.x as `Wurk::UniqueJobs`, answering to `SidekiqUniqueJobs` (and to `require "sidekiq-unique-jobs"` / `"sidekiq_unique_jobs"`) when the gem is not in the bundle. Every `lock:` type (`until_executed`, `until_executing`, `while_executing`, `until_and_while_executing`, `until_expired` and their aliases), `lock_args_method`, `lock_ttl`, `lock_timeout`, `lock_prefix`, `lock_info`, `on_conflict` (`:log`, `:reject` to the dead set, `:reschedule`, `:raise`, `:replace`, and `{ client:, server: }`), `unique_across_queues`, `unique_across_workers`, `SidekiqUniqueJobs.configure`, `Server.configure` with its death handler and reaper, `Digests#delete_by_digest`, `Locksmith`, `LockDigest` and `Lock::Validator::DEPRECATED_KEYS`. It writes the gem's own keys and digest (`uniquejobs:<md5>`, `:LOCKED`, `:QUEUED`, `:PRIMED`, `:INFO`, `uniquejobs:digests`), so a fleet drops the gem pod by pod with no migration and no lock gap; `test/ecosystem/sidekiq-unique-jobs-native/` runs a gem pod and a native pod on one Redis and holds them to each other. Its Lua declares every key it touches, so Dragonfly and a strict Redis 7 run it (the gem's `:replace` script does not). The reaper reads each job once per run instead of once per digest. With the gem in the bundle, the gem wins and the native copy stands down. `require "sidekiq_unique_jobs/web"` keeps the gem's Locks, Expiring Locks and Changelogs tabs on Wurk's dashboard. See `docs/unique-jobs.md` §13.
- **Native sidekiq-cron: drop the gem, keep the code and the Redis state.** Without the `sidekiq-cron` gem in the bundle, `Sidekiq::Cron` is Wurk's own implementation: `Sidekiq::Cron::Job` (`load_from_hash!`, `find`, `all`, `enable!`/`disable!`, …), `Sidekiq::Cron.configure`, `require "sidekiq/cron/web"`, over the gem's own `cron_jobs:<namespace>` / `cron_job:<namespace>:<name>` keys. Entries already in Redis keep their enabled/disabled state, which is keyed by name, so an edited schedule stays disabled. Fires are leader-gated and use the gem's `:enqueued` gate, so old pods on the gem and new pods on Wurk push each occurrence once; an interop run in the `ecosystem` job checks this against the real gem. With the gem bundled, Wurk stands down. The dashboard's Cron page lists the entries beside the periodic loops ([periodic jobs](../periodic-jobs.md#sidekiq-cron-natively-sidekiqcron)).
- **Documented and tested: a Gemfile with `gem "wurk"` alone.** Once no add-on declares `add_dependency "sidekiq"`, the `sidekiq` shim gem can go: Bundler resolves no `sidekiq` gem and every `require "sidekiq…"` path an app uses is a file in wurk's `lib/` ([migration guide](../migrate-from-sidekiq.md#dropping-the-shim-a-gemfile-with-wurk-alone)). The Sentry guide maps `config.sidekiq.report_after_job_retries = true` and a hand-written early-kill death handler onto `Wurk::Sentry.install!` ([Sentry](../sentry.md#coming-from-report_after_job_retries--true)).
- **`require "wurk/rspec"`: rspec-sidekiq's enqueue matchers.** `have_enqueued_sidekiq_job` and `enqueue_sidekiq_job` with rspec-sidekiq 5.x's chains (`with`, `on`, `at`, `in`, `immediately`, counts, negation, block form), so a suite drops that gem and the shim it needs. Opt-in; it does not switch fake mode on ([testing](../testing.md#11-rspec-sidekiqs-matchers-require-wurkrspec)). Ported, with credit, from an adopter's in-house replacement.

### Changed

- **The boot WARN and `wurk preflight --app` about `lock:` now ask whether a unique-jobs client middleware is installed**, gem or native, instead of whether the gem is loaded.

### Fixed

- **sidekiq-unique-jobs, native: the Locks tabs delete only by POST, and only a listed digest.** A GET to a delete route, from a read-only dashboard or another site's link, no longer drops locks, and `/locks/queue:default/delete` no longer unlinks an app key. Pages are capped at 1,000 rows and read in one pipeline; the reaper skips a run above 100,000 scheduled plus retrying jobs; `SortedEntry#delete` / `ScheduledSet#delete` return the set's result; `wurk preflight --app` no longer tells you to UNLINK `uniquejobs:*` when dropping the gem ([unique jobs §13](../unique-jobs.md#13-migrating-from-sidekiq-unique-jobs)).
- `bin/dummy-bundle` (run by `bin/setup`) no longer exits 1 under `pipefail` when Bundler has no `path` configured.
