# Unreleased

### Added

- **`wurk_jobs_dead_total{queue,class}`: a death counter the dead set's cap cannot hide.** The dead set is capped at `dead_max_jobs` (10,000 by default), so once full every kill evicts the oldest entry and `wurk_dead_size` stops moving: an alert on its `delta` can never fire on a busy cluster. Every move to the dead set that Wurk makes (retries exhausted, `:kill`, an API or dashboard kill, a poison pill, a payload the processor or scheduler cannot run) now also increments the `stat:deaths` hash, best effort (a failed count is reported to the error handlers, except inside the schedule-promote script, which drops it so the member still leaves its set; a reported error means the count may have been lost, not that it was), one field per queue and class (an ActiveJob's wrapped class), and `/metrics` exports it as a cluster-wide counter. New pairs past 500 fold into `queue="other",class="other"`; a kill written past `maxmemory` is not counted. The example `PrometheusRule` replaces `WurkDeadSetGrowing` with `WurkJobsDying` (`max by (queue, class) (increase(wurk_jobs_dead_total[1h])) > 10`) and `WurkDeadSetNearCap` ([metrics](../metrics.md#operational-gauges-on-the-health-listener)).
