# 1.7.6 — 2026-09-07

One runtime fix that matters to anyone using encrypted jobs — on json 3.0.0, every one of them failed — plus the repo hygiene that had accumulated since 1.7.5: the gate a contributor runs before opening a PR now checks what CI checks, the docs stopped claiming things the tree does not do, and three timing-sensitive tests stopped failing for reasons that were never the code. No Redis key, command sequence, job-JSON field, or public API changed: a 1.7.5 worker and a 1.7.6 worker can drain the same queue.

### Fixed

- **Every encrypted job failed once json 3.0.0 was resolved.** `Encryption.decrypt` called `JSON.parse(plain, quirks_mode: true)`, and json 3.0.0 removed that keyword — so the call raised `ArgumentError: unknown keyword: quirks_mode`. `decrypt` is on the job path, not just the test path, so this broke the server middleware for every encrypted job rather than only reddening CI. `Gemfile.lock` is gitignored by design, so no upgrade was needed to be exposed: any fresh resolve picked up json 3 and `main` went red with no PR at fault (10 errors, all `EncryptionTest`, while lint, parity and frontend stayed green). Dropping the keyword is safe rather than merely expedient — it was already a no-op. `quirks_mode` mattered only before json 2.0, when `JSON.parse` rejected a top-level scalar; RFC 7159 made any JSON value legal at the top level and json has parsed bare scalars by default ever since. A bare scalar is exactly the case an encrypted argument can produce, and it was verified on both json 2 and json 3. (#524)

- **`bin/check` refuses with exit 75 when its preconditions are unmet, instead of reporting a verdict it never earned.** A missing Redis exited 69 — `sysexits.h`'s `EX_UNAVAILABLE`, which the developerz.ai runner buckets as red (`verify_failed`) rather than "could not grade"; a missing bundler exited 1, which reads as "the gate ran and judged your change", telling an automated maintainer its correct edit was RED from a box with no Ruby toolchain at all. Both now exit 75, the platform's `CHECK_EXIT_PRECONDITIONS_UNMET` code (`EX_TEMPFAIL`). The refusal itself was already right — integration and parity tests use a real Redis, never a mock — only the number was wrong. `bin/check`'s four-value exit contract and the three env knobs it honours are now documented in CONTRIBUTING, having lived only in the script's source. (#472, #496, #474)
- **Four dead intra-doc anchors are fixed, and intra-doc links are gated in CI.** All four shared one root cause: the headings they target are numbered, and the links were written against the unnumbered slug — rendering as dead anchors on GitHub while looking fine in an editor. The gate keeps the class of bug from returning. (#460)
- **`docs/configuration.md`'s env table is actually complete now.** It claimed to list "Every `ENV` read in `lib/`" and missed `WURK_API_READ_ONLY` (read by `Configuration#api_read_only?`). The row is added and a test now fails when a new `lib/` env read has no row — the failure a completeness claim invites. (#463)
- **The `[Unreleased]` compare link can no longer go stale.** It compared from v1.7.3 through two releases because every version bump forgot it; it now compares from v1.7.5, and `release:check` fails when the link does not compare from the version being released. Two entries still pointing at the pre-1.7.1 name of `docs/compatibility.md` are repointed. (#485)

- **`bin/check` no longer grades a diff against gems it never loaded.** Bundler on `PATH` is not the same as the bundle being *installed*: a box with Ruby and bundler but no `bin/setup` failed every `bundle exec` stage with "Could not find gem …", which the script swallowed into its failure list and reported as exit 1 — "the gate ran and judged your change". It had not. `bundle check`, the same probe `bin/setup` already trusts for this question, now runs with the other preconditions and refuses with 75. This is the third layer of the same fix 1.7.6 makes twice above. (#521)

- **Three tests stopped failing for reasons that were never the code.** Each asserted against wall-clock or arrival order in a way a loaded box invalidates: the limiter's refill tolerance now follows the clock instead of a fixed slack, and a slow swarm boot is no longer read as a deadline failure (#518); the unique-kill and API-mutation sorted-set fixtures are seeded not-yet-due, so a worker cannot fetch them out from under the assertion (#519, #520); and the deadline job is pushed only once its child is actually fetching (#519). These are the failures that cost a reviewer the most, because the red is real and the cause is not in the diff.

### Changed

- **`.maintainer.yml` declares `services: [redis]`.** This repo's own gate refuses to run without a Redis on 127.0.0.1:6379, and that refusal is right. What was wrong was what happened next: every box in the fleet claimed this repo's coding work, the agent produced the correct edit, passed its own guard, and the gate discarded it in 60 ms for want of a service the box never had. Tasks now route only to boxes that can serve them; a task no box can serve is HELD with `no_service_capacity` naming the gap, instead of failing preconditions three attempts in a row. (#473)
- **The contributor tooling env vars are documented once, on the pages that own them.** A sweep of `bin/`, `bench/` and the `Rakefile` for env reads documented the ones a contributor actually sets (`docs/benchmarks.md`, `docs/profiling.md`), and three duplicate doc surfaces that each carried a diverging copy of the same knobs were collapsed into those. (#466)
- **The GitHub wiki is reviewable.** The wiki lived in a separate repo — no pull requests, no CI, zero gates over 8 pages and 2 commits — which is how "Free forever. Faster." shipped on the public front page and sat there for the wiki's entire life, contradicting `docs/benchmarks.md` (0.87×–1.02×) and the project's own rule against the claim. Source now lives in `docs/wiki/`, is published from CI, and is link-gated like the rest of the docs (#457). The content was rebuilt around that: a front door and navigation that serve three different readers (#458); an evaluation set — compatibility, performance, and a migration guide that goes past "that's it" (#459); a day-1 set — configuration, running, testing, and Active Job (#461); and the feature set — retries, reliability, unique jobs, and the Wurk-only extras (#462). The README now describes the wiki as short orientation pages that deep-link the `docs/` reference, not "the complete guide". (#464)
- **Auto-merge is on; the `main-protection` ruleset, not the policy file, is the merge gate.** `.maintainer.yml`'s `pr.auto_merge: false` described a protection that had already moved into the ruleset, and both prose blocks in the file claimed otherwise — falsely. They now say what actually protects `main`, and green PRs auto-merge. The file also notes that the ruleset sets `require_extra_approval_for_unattributed_changes: true`: a commit not attributed to a GitHub account costs its PR one human approving review. (#468, #501)
- **Repo docs stopped disagreeing with the tree.** `CLAUDE.md` carried three stale claims about the codebase (#492); the coverage-gate and PR-checklist wording described checks CI no longer runs that way (#479); the issue-chooser's contact link pointed at GitHub Discussions, which are disabled for this repo — it now opens a pre-labelled `question` issue (#481).
- **The dev environment is baked into `.devin/blueprint.yaml`.** A fresh session boots a cold copy of one org-wide snapshot and nothing persists between sessions, so every session paid a full cold setup before it could run `bin/check` once. That is not knowledge a session should rediscover, and it costs compute every time. (#465)
- **CI and tooling hygiene:** three workflow `paths` filters named the gitignored `Gemfile.lock` and so could never match it (#489); dependabot now also watches the Dockerfile base image (#507), whose `oven/bun` base tracks 1.4 (#510), and all four `bun-version` inputs were resynced to 1.4.0 to match it (#514); `bin/bench-compare` dropped a dead `(TODO)`-label skip (#487); directives for a Minitest cop that is disabled repo-wide are removed (#478).

- **`bin/check` now runs what CI runs.** Its header promised that a green local run is "the same answer the PR will get", while the `frontend (vitest)` job had no local equivalent at all — a dashboard change could pass `bin/check` and then fail CI on typecheck, oxlint or vitest. The frontend gate is now a stage in every mode except `fast` (`SKIP_FRONTEND=1` opts out), and a test asserts it keeps running the same commands, in the same order, as the CI job, so the mirror cannot quietly drift. `bin/check full` also runs the reference Python client's suite; the package build behind it happens in a throwaway virtualenv so the gate never installs into the interpreter a contributor is using, and a box that cannot bootstrap pip is reported as a missing precondition rather than a red diff. (#476, #475)

- **Workflows are linted on every PR.** An `actionlint` job (binary pinned by release, download-script commit SHA, and the binary's own SHA256) runs on every pull request, closing the gap left by an advisory review-lane pass that could never block a merge. It refuses to run at all if `shellcheck` is absent, because actionlint silently skips every `run:` block without it and still exits 0 — a green check that had quietly stopped checking. (#484)

- **The docs stopped claiming things the tree does not do.** Three public surfaces and `CLAUDE.md` said all six sidekiq-* ecosystem gems ran their upstream suites in CI; only `sidekiq-cron` has a harness, and the rest are tracked as target additions — the claim is corrected and now gated by tests that fail if a gem is named as running in CI without a harness on disk (#493). Seven places still described the parity suite as "lifted from Sidekiq" when it is independently written against the documented behaviour (#494). Comments across the workflows and the `Gemfile` still narrated the retired three-leg version matrix and a standalone coverage job that no longer exist (#490).

- **Repo furniture:** the Ruby toolchain is declared in `mise.toml` and installed by `bin/setup`, so a fresh box gets the interpreter CI uses without being told (#517); repo configuration moved under `.dz/` (#523); and the demo-deploy texts were aligned with the tag-as-output release lane (#515).
