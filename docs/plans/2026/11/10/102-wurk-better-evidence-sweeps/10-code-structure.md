## Rejected (do not do)
- Settings objects (`config.api.token`) — breaks Sidekiq-shaped API.
- Further Swarm/Launcher/Processor splits — cohesive lifecycle; hot path.
- Central `Wurk::Env` — ENV reads are local to owners and documented.
- Routing all `JSON.*` through `Wurk.dump_json` — `dump` vs `generate` differ; wire risk for churn.
- Centralising middleware registration — chain order is load-order by design (matches Sidekiq's i18n).
- Full RBS (~1,600 public defs) — no consumer. A core-surface RBS is a possible follow-up, not in this plan.
- Merging `Wurk::API::Serializers` with the dashboard serializers — two contracts.
- `Thread.current[:wurk_capsule]` → thread variable — behavior change (fiber-local today; `Wurk.redis` inside a Fiber/Enumerator resolves the default capsule pool — recorded as an open question in [`overview.md`](overview.md)).
