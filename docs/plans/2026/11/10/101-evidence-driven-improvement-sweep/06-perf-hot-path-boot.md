# 06 — Performance: hot path + boot

> Part of [`overview.md`](overview.md). Depends on: [`12`](12-proof-harness.md) T3 (command budget gate) — land it first so nothing here adds a command. One PR per row; each PR body names its bench and pastes before/after. No row may touch a Redis key, job JSON field or score format; if it would, drop the row.

Baseline (`docs/benchmarks.md`): Wurk 0.87x–1.02x of stock Sidekiq; behind on noop and boot (0.70s vs 0.54s). Redis is at its floor: 1 round-trip, 3 commands per busy-queue job (`LREM`+`DEL`+`LMOVE`) vs Sidekiq's 1 `BRPOP`. Remaining gap = Ruby CPU per job, never attributed: ~6 mutex acquisitions (`PROCESSED.incr`, `WORK_STATE.set`/`delete`, `ACCUMULATOR.add`, `defer_ack`, `take_pending_ack`), 2 `thread_variable_set`, 2 `handle_interrupt`, 8-frame dispatch onion (`lib/wurk/processor.rb:426-443`), ~9 server middleware entries vs ~1. Earlier single tweaks landed inside noise (benchmarks.md "What earned its place").

## Lazy loading (load tiers)

Measured 2026-11-10 @ `f6f509e`, `bundle exec ruby -Ilib -e 'require "wurk"'`, no Redis, host load avg ~8 (rough — redo on a quiet host with L0): **~333 ms, 404 loaded features, ~60k allocations, +15 MB RSS**. Split: Wurk's own files ~156 ms, `openssl` ~47 ms, `uri` ~38 ms, `redis_client` ~17 ms, `json` ~11 ms. `lib/wurk.rb` has 92 top-level requires and zero `autoload`. Every process pays the full set — a Puma worker that only enqueues loads `cli`, `swarm`, `embedded`, `topology`, `launcher`, `manager`, `processor`, `fetcher`, `scheduled`, `web`, `api` (+`rack`), `flow`, `limiter`, `cron`, `profiler`, `metrics/query`, `testing`.

Order: L0 → L1+L2+L4 as one PR (compile unit: tiers, aliases and pre-fork eager load must land together) → L5/L6/L7 only where L0 shows ≥3 ms or ≥1 MB.

Risks: (1) load-order bugs are exactly the adopter crash-loop class (`uninitialized constant Wurk::Engine`, `WurkAdapter`) — [`03`](03-boot-guards-preflight.md) G10 `wurk boot-check` must exist first and run in CI against `test/dummy` in all three entry points; (2) thread-safe autoload under Ruby 3.2 floor — run the 3.2 compat leg locally before push; (3) `Sidekiq::Testing` require paths (`require 'sidekiq/testing'`) must keep working with `Testing` lazy.

## Steps
1. P1 → publish → pick. Do not start P2 before the table is merged.
2. Each PR: `bin/rake bench` (regression vs own past) **and** `bin/rake bench:vs_sidekiq` (comparison). A green `bench` says nothing about Sidekiq.
