## Steps
1. M0 first; publish the baseline table in `docs/benchmarks.md` ("Memory") before changing anything.
2. M2+M3 land with or after [`06`](06-perf-hot-path-boot.md) L1/L4 — lazy loading without pre-fork force-load makes per-child PSS worse; M0 is the gate (per-child PSS must not rise).
3. Boot ordering in root `CLAUDE.md` is fixed: compaction happens after step 2 (app booted), before step 3/4 (close parent sockets, fork). Never open a Redis socket in the parent between compaction and fork.
