# test/ — how the suite works

- **Runner.** Minitest with `minitest-parallel_fork`: it forks `NCPU` workers and deals whole test classes to them (`SuiteBalance` orders them); a worker runs its classes and their methods serially on one thread. `parallelize_me!` is not an opt-in and changes nothing here: `Wurk::Test::UnitCase` stubs it empty (`test/test_helper.rb`) and the runner undoes Minitest's own (`Minitest::Unparallelize`). A class without it is forked the same. So two tests in one worker never overlap; a finding that asks to serialize them is wrong.
- **Workers.** `test_helper` defaults to half the cores, floored at 1 and capped at 4 (`Wurk::Test::DEFAULT_NCPU`), because the integration layer boots real swarms and one worker per core oversubscribes into wall-clock failures. `NCPU=<n>` overrides; `NCPU=1` chases an ordering flake.
- **Per-worker Redis DB isolation.** Each worker runs against its own Redis logical DB (1–14, with 15 reserved for fixed-DB tests; never DB 0), assigned in `test_helper`'s `after_parallel_fork` hook; `teardown` runs `FLUSHDB` so each test gets a clean slate. Tests that build a pool explicitly use `Wurk::Test.redis_url`. Concurrent suite runs on one Redis (several agents or terminals) each set `WURK_TEST_DB_OFFSET=<k>` so their workers don't share DBs. An overlap stops the second run with exit 75 naming the holder (`test/support/redis_db_lock.rb`); no Redis also exits 75. `test_helper` refuses DB 0. No test, bench or harness uses DB 0, `FLUSHALL` or `SCRIPT FLUSH` on a shared server; `test/ecosystem/redis_guard.rb` scans third-party checkouts for the same.
- **Layers:** unit · engine (boots `test/dummy/`) · integration (real forks + real Redis) · parity (`test/parity/`, independently written oracles for the documented Sidekiq behaviour, pinned to the upstream revision in `test/parity/.sidekiq_sha`) · conformance (`test/conformance/`, promise-to-oracle inventory and ledger anchors; runs with `bin/rake test:parity`) · ecosystem (third-party gem suites run against Wurk) · benchmarks.
- **Parity tests are oracles.** When Wurk diverges from a parity test, Wurk is wrong unless the divergence is explicitly documented as intentional in the canonical ledger, [docs/idea/parity-divergences.md](../docs/idea/parity-divergences.md). Write them from the documented behaviour; never copy upstream test files.
- **Never mock Redis** in integration or parity tests. Real Redis, unique namespace.
- **Wait on progress, not on time.** Poll a condition with a deadline; a fixed `sleep` is a flake on a loaded runner.
- **Doc claims are tests too.** `bin/rake test:guards` runs `test/guards.txt`: every test reading docs, policy or workflow files. A new one goes on that list. `test/unit/*_claims_test.rb`, `llms_txt_test.rb`, `llms_full_test.rb`, `docs_links_test.rb` and the `*_brief_test.rb` files read prose. A red one usually means the sentence is wrong, not the test.
- **Coverage gate.** SimpleCov **line** and **branch** coverage on `lib/` must both stay ≥90% (blocking; `minimum_coverage line: 90, branch: 90`). Coverage runs merge across the workers via `SimpleCov.at_fork`; a merge that lacks any forked worker's resultset fails the run as `coverage merge incomplete: missing worker-N` and reports no percentage (`test/support/coverage_merge.rb`). A test that spawns a repo script must unset `COVERAGE` for it — `bin/check` runs `rm -rf coverage`, which is the live run's data.
